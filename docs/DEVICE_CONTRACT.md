# Device contract and configuration guide

The app contains **no** device-specific BLE UUIDs, MQTT topics, payload formats or Matter
endpoints. Every value is entered in *Setup* and stored locally (non-secret values in app
preferences, passwords in the Android Keystore-backed `SecretStore`). Until a value is present,
the UI and `getStatus` show it as **PLACEHOLDER** and the adapter refuses to initialise, so an
unconfigured path cannot produce a result.

The only constants in the code are protocol-standard ones: the Bluetooth SIG CCCD descriptor
`0x2902`, the Matter BLE service `0xFFF6`, the Matter OnOff cluster/attribute IDs and the Matter
test vendor id `0xFFF1`.

## Values required from the firmware (Appendix A.C)

### BLE
| Field | Setup key | Notes |
|---|---|---|
| Service UUID | `serviceUuid` | 128-bit; also used as scan filter |
| Command characteristic | `commandCharUuid` | must support write (with response recommended) |
| Ack/response characteristic | `responseCharUuid` | must support notify or indicate; CCCD 0x2902 required |
| State characteristic | `stateCharUuid` | only for `readMode = GATT_READ` |
| Write with response | `writeWithResponse` | |
| Payload format | `codec.*` | see templates below |
| Op-id echo | `codec.ackOpIdField` | JSON field the firmware copies the op id into |

### MQTT v5
`host`, `port`, `useTls` (or explicit `allowInsecureLab`), `clientId`, `commandTopic`, `ackTopic`,
optional `stateTopic`, `qos`, optional `username` (+ password via *Store*), `codec.*`.

The firmware **must** publish an application-level acknowledgement on `ackTopic` *after* applying
the command. The app also sends MQTT 5 `Response Topic = ackTopic` and
`Correlation Data = op id` (toggle `useMqtt5RequestResponse`); firmware that echoes Correlation
Data is matched even if the payload carries no op id.

### Matter
`endpointId` of the OnOff server endpoint; `clusterId = 6`, `attributeId = 0`,
`writeMode = INVOKE_ONOFF` (the only mapping this controller build supports; other values are
rejected as UNSUPPORTED, never approximated). `nodeId` is filled in by commissioning.
Commissioning needs the device discriminator and setup passcode (from its QR/manual code), plus the
Wi-Fi SSID/password for BLE→Wi-Fi provisioning, or the device IP for on-network commissioning.

## Payload templates (`codec`)

Templates are literal text with placeholders `{op_id}`, `{op}` (`READ_STATE`/`WRITE_STATE`),
`{value}`, `{pad}`. `{pad}` is filled with `x` so the encoded message is exactly
`payloadSizeBytes` long (if requested). Acknowledgements are parsed as JSON objects; the op id is
read from `ackOpIdField`, optional success from `ackStatusField == ackOkValue`, optional resulting
state from `ackValueField` (if present, the runner checks it equals the written value and records
`VALIDATION_FAILED` otherwise).

## PROPOSED firmware contract (not applied automatically)

If the firmware does not have a format yet, this is a minimal proposal the firmware author may
adopt. It is **not** a default in the app; it must be typed into Setup only if the firmware
implements it.

```text
write template:  {"id":"{op_id}","op":"{op}","v":{value},"pad":"{pad}"}
read template:   {"id":"{op_id}","op":"{op}","pad":"{pad}"}
ack (device→phone, after applying):  {"id":"<same op id>","st":"ok","v":<current state>}
ackOpIdField=id  ackStatusField=st  ackOkValue=ok  ackValueField=v
```

Same logical state for all three paths (spec §4.3): e.g. one LED, `v = 1` on / `0` off, mirrored
by the Matter OnOff attribute when the same board exposes multiple paths.

## Semantic differences that cannot be removed (documented for the thesis)

| Path | Completion boundary | Note |
|---|---|---|
| BLE (COMMAND) | correlated notification/indication from firmware | GATT write callback recorded separately |
| BLE (GATT_READ) | onCharacteristicRead | no op-id echo; device GATT server responds |
| MQTT v5 | correlated message on ackTopic | includes broker hop twice; PUBACK is diagnostic only |
| Matter write | InvokeResponse SUCCESS | generated by device data model after executing; no state echo |
| Matter read | ReportData for OnOff attribute | |
